# MemoryHub — 跨渠道 AI 记忆中枢

> 一套**独立的**记忆服务，让 Minecraft 里的 NPC、QQ 群机器人、直播弹幕机器人
> 共用同一份记忆，彼此记得对方渠道发生过的事。
>
> **状态：设计阶段，代码未开始。** 当前只有方案文档，没有实现。

---

## 这个目录是什么

它是**一个独立系统**，不是 MC 插件的子模块。

- 用 **Rust** 写，与 MC 插件（Java）只通过 HTTP/JSON 通讯
- 部署形态目标：**一个二进制 + 一个 `.db` 文件**
- MC 停服它照样跑，它挂了 MC 照样跑

代码、配置、数据、备份策略都与 MC 插件解耦。

```
MemoryHub/
├── README.md      ← 你在这里

```

## 三条不看会踩的实测事实

这些不是推测，是在本机真跑出来的：

**1. 直接拷贝 `memory.db` 会静默丢数据。**

```
主库 388 KB，WAL 里还有 286 KB 没合并（74%）
cp memory.db  → journal 403 条   ❌ 丢 5 条，零报错
VACUUM INTO   → journal 408 条   ✅ 与真实库一致
```

**2. SQLite 版本带着已确认的 WAL-reset bug。**
官方 `wal.html §11`：影响 3.7.0–3.51.2，修复在 3.51.3。
本项目 Java 侧 `sqlite-jdbc:3.44.1.0` 含 bug；而 `shared_dir` 的
多进程共享拓扑**正是官方说的触发条件**。

**3. 业务数据只有 388 KB，但诊断数据有 10 MB。**
`transcripts/`（10 MB）+ `usage/`（0.7 MB）**一条都不该进这里**。
搞错这条，新服务会白白背上 10 MB 请求日志。

## 铁律

1. **备份只用 `VACUUM INTO` 出快照**，绝不 `cp`/`rsync`/`tar` 直抓 `.db`。
2. **不共享 `.db` 文件跨机器**。WAL 依赖共享内存，网络文件系统上会损坏。
   多台机器共享记忆**只能走 HTTP 接口**。
3. **身份绑定必须人工确认**，不自动猜。猜错会把两个人的记忆混成一个人，不可逆。
4. **时间轴以 `at_ms`（现实 UTC 毫秒）为唯一主轴**。游戏日 `g<N>` 只是 MC 渠道的附加标签。
5. **代码里不出现绝对路径**，不依赖 macOS 专有 API（部署要可迁移）。

## 已定的事实（不用再讨论）

| 项 | 决定 | 依据 |
| --- | --- | --- |
| 语言 | **Rust** | 用户指定 |
| HTTP 栈 | `axum 0.8` + `tokio` | 本机实测跑通 |
| 存储 | `rusqlite 0.41`（bundled SQLite **3.54.1**） | 实测；该版本已修复 WAL-reset bug |
| 协议 | **REST/JSON**；MCP 只做可选门面 | 三个渠道调用时机都是确定性的 |
| 用不用现成框架 | **不用** | mem0/Zep/Letta 全要 Postgres+pgvector，graphiti 必须 Neo4j |
| 用不用向量库 | **暂时不用** | 当前 `fact` 只有 10 行，没有语义检索的素材 |
| 主备份工具 | **restic** | rustic 官网自述 beta、不建议生产，且与 restic 锁不兼容 |
| 用不用 litestream | **不用** | Go 常驻进程；恢复粒度只能落在现存 LTX 边界 |
